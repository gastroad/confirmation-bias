# Handoff

**main 워크트리는 "무엇을 할지"만 정하는 자리입니다.** 여기서 방향이 정해지면 실제 작업은
별도 워크트리의 독립 Claude 세션이 이어받습니다. 이 커맨드가 그 인계를 수행합니다.

`orca worktree create --agent claude`로 띄운 세션은 **Orca가 관리하는 별도 프로세스**입니다.
Task 툴 서브에이전트와 달리 이쪽 컨텍스트를 쓰지 않고, 이쪽 턴이 끝나도 계속 살아 있습니다.

## 절차

### 1. 논의를 컨텍스트로 압축한다

대화에서 **합의된 것만** 추립니다. 목표 분량은 3~8줄.

- 쓸 것: 무엇을 할지, 왜 하는지, 하지 않기로 한 것, 논의 중 나온 제약·전제
- **쓰지 않을 것**: 설계·구현 방법·파일 목록·단계별 계획.
  그건 넘겨받는 세션이 코드를 보고 판단합니다. 여기서 정하면 틀린 채로 굳습니다.
- **CLAUDE.md와 `docs/agent/*`를 프롬프트에 복붙하지 않습니다.** 새 세션이 자동으로 읽습니다.
- 논의되지 않은 건 추측해서 채우지 않습니다. 비워 두면 그쪽에서 묻습니다.

### 2. 브랜치 이름을 정한다

`feat/` · `fix/` · `chore/` · `docs/` + kebab-case 슬러그.
인자가 주어졌으면(`$ARGUMENTS`) 그것을 쓰고, 없으면 논의 주제에서 만듭니다.

### 3. 사용자에게 확인받는다

압축한 컨텍스트와 브랜치 이름을 그대로 보여주고 승인을 받습니다.
**승인 없이 워크트리를 만들지 않습니다.**

### 4. 워크트리를 만들고 넘긴다

```bash
orca worktree create \
  --repo name:confirmation-bias \
  --name <브랜치명> \
  --agent claude \
  --prompt "<압축한 컨텍스트>" \
  --json
```

생성과 동시에 리포에 등록된 setup 훅이 함께 돕니다(별도 조치 불필요).

| 훅                 | 하는 일                                              |
| ------------------ | ---------------------------------------------------- |
| `orca-seed-env.sh` | main 워크트리의 `.env`·`.env.*`를 새 워크트리로 복사 |
| `orca-draft-pr.sh` | 씨앗 커밋 + `main` 대상 **draft PR** 생성            |
| `npm install`      | `postinstall`이 `prisma generate`까지 수행           |

- `--activate`는 붙이지 않습니다. Orca 화면이 새 워크트리로 튀지 않고 백그라운드로 뜹니다.
  (사용자가 "바로 열어 줘"라고 하면 그때만 붙입니다.)
- `--base-branch`도 붙이지 않습니다. 리포 기본 base(`main`)를 씁니다.
  현재 브랜치 위에 쌓아야 하는 작업이면 그건 논의 단계에서 나왔어야 합니다.

### 5. 보고하고 끝낸다

응답의 `result.path`와 브랜치명, draft PR URL(훅 로그에 있음)을 알립니다.

**여기서 멈춥니다.** 이건 full handoff입니다.
`terminal read`·`terminal wait`로 진행 상황을 들여다보지 않고, 결과를 기다리지도 않습니다.
소유권이 넘어갔으므로 진행 상황은 사용자가 Orca에서 직접 봅니다.

## 작업이 끝난 뒤 (사용자가 PR을 머지한 후)

main 워크트리로 돌아와 최신화하고 정리합니다.

```bash
git pull
orca worktree rm --worktree branch:<브랜치명>
```

`worktree rm`은 워크트리와 함께 로컬 브랜치도 지웁니다(머지가 확인된 것만).
