## 점검에서 드러난 것

### 시사인 — 죽은 피드

`sisain.co.kr/rss/S1N6.xml`이 응답은 하지만 **최신 기사가 2023-03-22**다(1,251일 전).
DB의 2023-03 이상치 20건이 전부 여기서 왔다.

피드에서 뺐지만 **`OUTLETS`에는 남긴다** — 기존 기사 20건의 출처이고, 지우면 FK가 깨진다.
필터에는 계속 뜨지만 새 기사가 들어오지 않는다.

### 중앙일보 · KBS — 피드가 아예 없었다

`OUTLETS`에 등록만 되어 있고 `feed_specs.json`에는 없었다. 기사 0건.
대체 URL을 여럿 시도했으나(`rss.joins.com`, `news.kbs.co.kr` 등) 모두 RSS가 아닌 응답을 준다.
두 곳 모두 RSS 제공을 중단한 것으로 보인다. **목록에서 제거했다.**

### 프레시안 — 제목에 `&`가 빠진 HTML 엔티티가 온다

프레시안 피드의 **원본 XML에 literal `quot;` · `hellip;` · `middot;` 가 들어 있다**
(`&`가 없다, 2026-08-27 원문 확인). 우리 파서 문제가 아니라 발행 쪽 인코딩 버그다.

```
<title>김민석 quot;이진숙, 앞으로 '여자 전두환'이라고 부르겠다quot;</title>
```

그대로 두면 `김민석 quot;…quot;` 같은 제목이 목록·상세·검색 결과·OG에 그대로 나간다.
실측으로 **기사 608건(2.3%) · 클러스터 대표 제목 185개(1.7%)** 가 이 상태였다.

`server/feed-entities.ts`가 정상 엔티티(`&quot;`)와 `&`가 빠진 잔재(`quot;`)를 **순서대로**
처리한다. 한 패스로 합치면 이중 인코딩(`&amp;quot;`)에서 `&amp;`와 `quot;`가 각각 잡혀
`&"`가 되므로 나눠야 한다. 잔재 복원은 원문을 건드리는 일이라 **알려진 이름 목록만** 바꾼다.

**URL에는 적용하지 않는다.** 프레시안 링크에 `&amp;ref=rss`가 섞여 오지만 `Article.url`이
`@unique`라, 지금부터 디코딩하면 같은 기사가 옛 URL과 새 URL로 두 번 적재된다.
링크 자체는 정상 동작한다.

기존 데이터는 `npm run repair:titles`로 복원했다(멱등).

### `pubDate`가 없는 피드 — 발행 시각이 수집 시각으로 대체되고 있었다

경향신문·프레시안은 RSS 2.0의 `pubDate`가 아니라 **Dublin Core `dc:date`** 를 쓴다.
`collect.ts`가 `pubDate`만 보던 탓에 파싱이 실패해 **수집 시각으로 대체**됐다 —
일별 버킷이 실제 발행일과 어긋날 수 있었다.

`pickPublishedRaw()`가 `pubDate` → `dc:date` 순으로 본다. 수정 후 프레시안 기사의
발행 시각이 수집 시각과 달라진 것으로 확인했다.

**한겨레는 여전히 수집 시각으로 떨어진다** — item에 날짜 태그가 아예 없고
`lastBuildDate`만 채널 레벨에 있다. RSS가 최신순이고 3시간마다 수집하므로 오차는 크지 않다.

## `feed_specs.json`은 politics만 남겼다

이전에는 economy·society·international까지 4개 카테고리 × 13곳 = 52개가 정의돼 있었으나,
**`collect.ts`는 `politics`만 읽는다.** 나머지 39개는 죽은 설정이라 오해를 부르므로 제거했다.
카테고리를 늘릴 때 다시 넣는다.

## description은 300자로 자른다

일부 언론사(뉴시스·서울신문·천지일보)는 RSS `description`에 **요약이 아니라 본문 전문**을
실어 보낸다(실측 최대 7,681자). 그대로 저장·표시하면 저작권 문제가 된다.

`collect.ts`의 `toExcerpt()`가 300자로 자른다. 300자는 RSS 관행이기도 하다 —
동아·여성신문·시사저널·미디어오늘이 이 길이로 잘라 보낸다.

부수 효과로 **임베딩 입력 길이가 매체 간에 고르게 맞춰진다.** 전에는 300~7,681자로 들쭉날쭉해
긴 요약을 주는 매체가 더 많은 정보로 임베딩됐다.

## 저작권자의 표시 중단 요청

약관은 "지체 없이 삭제하고 이후 수집에서도 제외한다"고 약속한다. **기사를 지우기만 하면
3시간 뒤 RSS에서 그대로 재수집된다** — `collect`는 URL 중복만 막지 삭제 이력을 모른다.

`/admin/blocked`에서 기사 주소를 등록하면 한 트랜잭션으로 둘 다 처리한다:

1. `BlockedUrl`에 등록 → `collect`가 이후 수집에서 건너뛴다
2. 이미 저장된 기사 삭제 (+ 소속 클러스터의 `articleCount` 보정)

아직 수집되지 않은 주소도 미리 넣을 수 있다. 매체 전체를 빼야 하면 `feed_specs.json`과
`OUTLETS`에서 제거한다(위 "언론사를 더할 때" 절의 역순).

**차단을 해제해도 이미 지운 기사가 되살아나지는 않는다.** 다음 수집에 다시 들어온다.

## 피드 점검하는 법

수집이 줄었다고 느껴지면 언론사별 유입을 먼저 본다:

```sql
select o.name,
       count(a.id) filter (where a."bucketDate" >= current_date - 7) as last7,
       max(a."publishedAt") as latest
from "Outlet" o left join "Article" a on a."outletId" = o.id
group by o.name order by last7;
```

`last7`이 0이면 그 피드를 직접 열어본다. 판정 기준은 **응답 여부가 아니라 최신 기사 날짜**다 —
시사인처럼 200 OK로 3년 묵은 항목을 돌려주는 경우가 있다.

- **User-Agent를 붙이지 말 것.** `collect.ts`는 헤더 없이 요청한다. UA를 붙이면 한겨레가
  403을 주는 등 실제와 다른 결과가 나온다.
- 리다이렉트를 따라가야 한다(한겨레는 `/rss/politics/` → `/rss/politics`).

## 언론사를 더할 때

1. 피드를 직접 열어 **최신 기사 날짜**와 `pubDate`/`dc:date` 유무를 확인
2. `src/entities/outlet/model.ts`의 `OUTLETS`에 추가 (성향 균형을 볼 것)
3. `scripts/feed_specs.json`의 `politics`에 추가
4. `npm run db:seed` — upsert이며, 목록에서 빠진 **기사 0건짜리** 언론사는 자동 정리된다
