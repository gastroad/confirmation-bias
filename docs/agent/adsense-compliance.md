### 댓글·회원가입으로는 해결되지 않는다

2026-08-24에 도입한 댓글·회원가입은 이 위반의 답이 **아니다.**

- 정책이 요구하는 건 기능이 아니라 **페이지 위의 부가가치**다("논평을 추가하거나, 선별 게재
  또는 기타 부가가치"). 댓글 입력창은 논평이 아니라 논평을 받을 그릇이고, 현재 1만 페이지에
  댓글이 1개다. 빈 댓글창은 오히려 방치된 사이트 신호로 읽힌다.
- UGC는 통과를 돕기보다 **새 리스크를 만든다.** 사용자 생성 콘텐츠가 있으면 관리·신고 체계를
  요구받고, 정치 뉴스 댓글은 별도 정책(혐오·명예훼손)에 걸릴 수 있다.
- 닭과 달걀이다. 트래픽 없는 신규 사이트에 댓글이 쌓일 리 없고, 기다리는 동안 심사는 계속
  떨어진다.

### P0-6. 색인에서 뺀 껍데기가 **사이트에는 그대로 있다** (2026-10-22 진단)

**`noindex`는 Google 검색 색인에만 작용한다. AdSense 심사자와 크롤러가 사이트를 돌아다니는
것은 막지 않는다.** 2026-08-27 이후 이 문서는 "색인만 빼고 접근은 열어 둔다"를 해결로
적어 왔는데, **"가치가 별로 없는 콘텐츠" 판정의 대상은 색인이 아니라 사이트다.**

| 구분                      | 페이지 수  | 전(robots)        | 후           |
| ------------------------- | ---------- | ----------------- | ------------ |
| 색인 대상 클러스터        | 4,417      | `index, follow`   | 그대로       |
| **기준 미달 클러스터**    | **22,691** | `noindex, follow` | **404**      |
| 날짜 (색인 대상 / 미달)   | 116 / 11   |                   | 그대로       |
| 언론사·정적               | 23         |                   | 그대로       |
| **크롤 가능한 총 페이지** | **27,259** |                   | **약 4,600** |

미달 22,691개의 내부 구성 — **"단독 보도"와 같은 집합이 아니다.** 이게 구현의 함정이었다.

| 분류                      | 개수      | 전에 어디 있었나     |
| ------------------------- | --------- | -------------------- |
| 비색인 · 단독 보도(1개사) | 19,437    | 접힌 블록, 링크 있음 |
| **비색인 · 2개사 이상**   | **3,254** | **본 목록에 카드로** |

그래서 **단독 보도(언론사 1곳) 기준으로 가르면** 3,254개가 본 목록에 남아 404로 가는 링크를
뿌린다. `partitionByIndexable`을 따로 두고 옛 `partitionBySpread`를 **제거한** 이유다 —
배럴에 남겨 두면 같은 실수를 다시 부른다.

껍데기 22,691개는 **링크로 도달 가능하다** — 날짜 페이지의 "단독 보도" 접힌 블록이
`/clusters/<id>`로 링크한다(`ClusterFeed`의 `soloList`). `robots.txt`도 `/api/`만 막는다.
즉 심사자가 사이트를 둘러보면 **84%가 헤드라인 한 줄짜리 페이지**다.

**✅ 2026-10-22 완료 (PR 아래).** 선택은 **404**였다 — 410은 Next에 API가 없어 `proxy.ts`에서만
가능하고 그러면 모든 `/clusters/*` 요청에 DB 왕복이 붙는다. Google은 404와 410을 거의 같게
처리하고, 이 서비스는 재클러스터링마다 id가 바뀌어 URL 영속성 기대가 애초에 낮다.

구현은 세 덩어리였다.

1. **`loading.tsx`를 전부 제거했다.** 이게 없으면 나머지가 무의미하다 — Suspense 경계가
   있으면 응답이 200으로 먼저 스트리밍돼 `notFound()`가 **soft 404(200 + noindex)** 가 된다.
   실측으로 라이브가 그 상태였다(`/clusters/<없는 id>` → 200).
2. **`shouldRemoveCluster()`** — 기준 미달이고 **댓글이 없으면** 404. 판정은 `entities/cluster`에,
   호출은 `clusters/[id]/page.tsx`에 둔다.
3. **목록을 색인 기준으로 가른다**(`partitionByIndexable`). 본 목록엔 색인 대상만 링크하고
   나머지는 접힌 블록에 **제목만, 링크 없이** 둔다 — 건수는 밝히므로 P1-3은 유지된다.

검증 (프로덕션 빌드):

| 경로                          | 상태 |
| ----------------------------- | ---- |
| 없는 id                       | 404  |
| 기준 미달 (기사 1건)          | 404  |
| 색인 대상 (기사 20건)         | 200  |
| 잘못된 날짜 (`/d/2026-13-99`) | 404  |
| 홈 · 정상 날짜                | 200  |

**부수 효과 — P0-5가 완성됐다.** 경계가 사라져 본문이 `<div hidden>` 스트리밍을 타지 않고
**HTML에 그대로** 실린다. JS를 실행하지 않는 크롤러도 읽는다.

| 경로        | 전 (인라인/전체) | 후 (인라인/전체)     |

| `/`         | 39 / 1,400       | **1,400 / 1,400** ✅ |
| `/d/[date]` | 39 / 1,390       | **1,390 / 1,390** ✅ |

`loading.tsx`를 **전부 제거했다.** 처음엔 날짜 세그먼트에 남겼는데 광고가 뜨는 72개 중

      레거시가 빠지는 속도(**월 약 400**)보다 빨라서다 — 순증 월 900.

      **45일 고정된 sitemap(P0-7)이 신규를 제출조차 못 하고** 있었다. 410으로 바꾸면(P0-6-a)
      레거시 제거가 빨라진다.

#### 순서 — 왜 바로 재심사를 넣지 않는가 (2026-10-22 결정)

실적을 재어 보니 **색인이 줄어드는 것을 기다리는 것이 트래픽 문제를 해결하지 못한다.**
색인이 줄면 노출은 **더** 떨어진다. P0-6(껍데기 404)도 노출을 더 깎는다 — 지금 노출
2,327회가 바로 그 클러스터 페이지들에서 나오기 때문이다.

버려도 되는 노출이다(클릭 23회·복제 헤드라인 기반·AdSense가 지적한 바로 그것). 그러나
**"사용자 관심"을 보여야 하는 시점에 숫자가 내려간다**는 점은 인지하고 순서를 정한다.

1. **P2-2 먼저** — 노출을 **올리는** 유일한 무료 작업이다.
2. **P0-6** — 규정 준수. 노출을 깎지만 깎아도 되는 쪽이다.
3. **재심사** — 노출·클릭이 **회복 추세로 돌아선 뒤**. 하락 중인 숫자를 보여주지 않는다.

> P0-6을 먼저 하면 재심사 시점에 "하락 중"만 남는다. P2-2를 먼저 하면 **적어도 추세가
> 반대로 돌 여지**가 생긴다. 둘 다 해야 하므로 순서만 정하는 문제다.

> **2차 거절이 말해 주는 것.** P0/P1을 다 채우고도 떨어졌으므로 **체크리스트 완주가 통과
> 조건이 아니다.** 2026-10-22 조사로 원인 후보가 네 개로 좁혀졌고, 그중 **셋은 코드 문제이고
> 하나는 아니다.**
>
> | #    | 원인                                    | 코드로 되는가            |
> | ---- | --------------------------------------- | ------------------------ |
> | P0-4 | 요약 문장 건수 중복 (색인 대상의 56.8%) | ✅ 고쳤다                |
> | P0-5 | 초기 HTML 본문 132자                    | ✅ 고쳤다                |
> | P0-6 | 껍데기 22,691개가 사이트에 그대로       | ✅ 가능 (제품 결정 필요) |
> | P0-7 | sitemap 45일 고정                       | ✅ 가능                  |
> | P2-1 | **실제적인 사용자 관심(트래픽)**        | ❌ 아니다                |
>
> **네 건 모두 "브라우저로 보면 멀쩡한" 종류였다.** 전부 HTML·sitemap·DB를 직접 조회해
> 찾았다. 셀프 점검 5·6번이 그 방법이다.
>
> **그리고 P2-1이 실측으로 확인됐다** — 클릭 0.25회/일. 코드 네 건을 다 고쳐도 이 항목이
> 남는다. 이것이 2차 거절의 주된 이유일 가능성이 가장 높다.

### 셀프 점검 — 심사자 시뮬레이션

재심사 요청 전에 직접 해본다.

1. sitemap에서 클러스터 URL을 **무작위로 5개** 열어본다.
2. 각 페이지에 **우리가 쓴 문장이 3줄 이상** 있는가?
3. 각 페이지에 **서로 다른 성향의 매체가 2개 이상** 등장하는가?
4. 이 페이지가 원문 기사 대신 존재할 이유를 한 문장으로 말할 수 있는가?
5. **`curl`로 받은 HTML에 그게 다 들어 있는가?** (2026-10-22 추가)
6. **광고가 뜨는 모든 경로**(6개 — [infrastructure.md](./infrastructure.md))에 5번을 해 본다.

하나라도 아니오면 아직이다.

**2026-08-27 결과** — sitemap에 남은 URL은 전부 기준을 통과한 것이라 1·2·3은 구조적으로 보장된다
(요약 문장 2~3줄 + 진영 2개 이상). 4번("원문 대신 존재할 이유")의 답도 페이지에 문장으로 적혀
있다 — **누가 침묵했는가.**

**5·6번을 왜 넣었나 (2026-10-22).** 1~4번을 **브라우저로** 하면 통과한다. 그런데 2차 심사는
떨어졌고, 원인 두 건은 둘 다 브라우저로는 안 보이는 것이었다.

- `curl`로 홈을 받아 보니 본문이 **132자**였다 — 브라우저에서는 이슈가 153개 보였다(P0-5).
- 요약 문장의 건수 중복은 화면에서도 보였지만, **`meta description`으로 나간다**는 점이
  중요했다. 화면을 눈으로 훑을 때는 "7곳 … 등 7곳"이 자연스러워 보여 넘어갔다(P0-4).

> **눈으로 보지 말고 HTML을 읽는다.** 심사자는 사람이지만 크롤러가 먼저 본다.
>
> ```bash
> curl -s https://www.confirmationbias.app/ | python3 -c "
> import sys,re,html
> b=re.search(r'<body[^>]*>(.*)</body>', sys.stdin.read(), re.S).group(1)
> for p in [r'<script[\s\S]*?</script>', r'<style[\s\S]*?</style>', r'<!--[\s\S]*?-->']:
>     b=re.sub(p,'',b)
> t=re.sub(r'\s+',' ',html.unescape(re.sub(r'<[^>]+>',' ',b))).strip()
> print(len(t), t[:300])"
> ```
>
> 이제 `e2e/home.spec.ts`의 "첫 화면 SSR" 절이 이 점검을 자동화한다.

## 이 서비스의 통과 가능성 — 정직한 평가

**가능하다. 단 두 번 떨어졌고, 세 번째도 보장은 없다.**

뉴스 애그리게이터는 AdSense 심사에서 원래 난이도가 높은 카테고리다. 금지는 아니지만 부가가치
입증 책임이 전적으로 우리 쪽에 있다. 다행히 이 서비스에는 **입증할 부가가치가 실재한다** —
"같은 사건을 진보/보수가 어떻게 다르게 다뤘는가, 누가 침묵했는가"는 원문 어디에도 없는
정보이고, 그걸 계산하는 파이프라인이 이미 매일 돌고 있다.

문제는 그 결과가 **문장으로 존재하지 않는다**(P0-2)는 것과 **가치가 성립하는 11%에 나머지
89%를 섞어 색인했다**(P0-1)는 것이다. 둘 다 코드로 해결 가능한 문제다.

**2026-08-27 갱신 — 둘 다 해결했다.** 모든 클러스터에 자체 작성 문장이 들어갔고, 색인은
기준을 통과한 18.5%로 좁혔다. 여기에 복제가 0인 페이지 20개(`/about`·`/outlets`·`/weekly`)를
더했다. 남은 변수는 코드가 아니라 **시간**이다 — noindex가 크롤러 재방문으로 반영되기까지
수 주가 걸리고, 그전에 재심사를 넣으면 심사자가 예전 색인 상태를 볼 수 있다.

**2026-10-22 갱신 — 그 상태로 넣어서 또 떨어졌다.** 그래서 "시간만 남았다"는 2026-08-27의
판단은 **절반만 맞았다.** 코드에 남은 결함이 두 건 더 있었고(P0-4·P0-5), 둘 다 공통점이
있다 — **브라우저로 보면 멀쩡하고 HTML로 받으면 아니었다.**

그 둘을 고친 지금, 다음 재심사의 변수는 다시 둘이다.

1. **색인 반영 상태** — 이건 이제 추측이 아니라 Search Console에서 **확인할 수 있다.**
   두 달이 지났으니 8,700여 개가 실제로 빠졌는지 수치로 보고 넣는다.
2. **아직 못 본 결함** — 찾는 방법은 셀프 점검 5·6번이다. 두 건 모두 그렇게 찾았다.

**세 번째 거절이 오면 체크리스트를 늘리지 말고 통보 문구를 그대로 여기 옮겨 적는다.**
1차 통보의 두 항목("복제된 콘텐츠"·"가치가 별로 없는 콘텐츠")만 가지고 두 번을 추측했고,
두 번 다 추측이 부분적으로만 맞았다.

## 부록 — 진단 재현 쿼리

```sql
-- 클러스터 크기 분포
SELECT "articleCount" AS n, count(*) FROM "Cluster"
WHERE "articleCount" <= 6 GROUP BY 1 ORDER BY 1;

-- 성향 다양성 분포 (spread = 등장하는 leaning 종류 수)
SELECT spread, count(*) FROM (
  SELECT c.id, count(DISTINCT o.leaning) AS spread
  FROM "Cluster" c
  JOIN "Article" a ON a."clusterId" = c.id
  JOIN "Outlet" o ON o.id = a."outletId"
  GROUP BY c.id
) t GROUP BY 1 ORDER BY 1;

-- P0-1 색인 기준별 잔존 페이지 수
WITH c AS (
  SELECT cl.id, cl."articleCount" AS n,
         count(DISTINCT CASE WHEN o.leaning IN ('left','center_left') THEN 'prog'
                             WHEN o.leaning IN ('right','center_right') THEN 'cons'
                             ELSE 'neut' END) AS groups
  FROM "Cluster" cl
  JOIN "Article" a ON a."clusterId" = cl.id
  JOIN "Outlet" o ON o.id = a."outletId"
  GROUP BY cl.id, cl."articleCount"
)
SELECT count(*) AS total,
       count(*) FILTER (WHERE n >= 3 AND groups >= 2) AS keep
FROM c;

-- 자체 작성 텍스트 존재 여부 / 복제 텍스트 길이
SELECT count(*) FILTER (WHERE summary IS NOT NULL) AS with_summary FROM "Cluster";
SELECT avg(length(description))::int, max(length(description)) FROM "Article";

-- 오염 날짜
SELECT "bucketDate"::text, count(*) FROM "Cluster"
WHERE "bucketDate" < '2026-06-01' GROUP BY 1 ORDER BY 1;

-- P0-4 요약 문장의 건수 중복 ("… 등 7곳)" 처럼 괄호 안에서 다시 센 것)
-- 고친 뒤에는 0이어야 한다. 0이 아니면 백필이 안 돌았다.
SELECT count(*) FROM "Cluster" WHERE summary ~ '등 [0-9]+곳\)';
```
