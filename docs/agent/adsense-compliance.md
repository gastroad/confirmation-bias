**핵심 진단 두 줄.**

1. 우리 서비스의 부가가치(성향 분포·보도량 비교)는 **막대그래프와 숫자로만 존재하고 문장으로

   그 넷을 덮으려면 `summary`를 DB에 채워야 한다.)
2. 그 부가가치가 **성립하는 페이지는 11%인데 100%를 색인에 올렸다.** 심사자가 `/clusters/<id>`를
   랜덤으로 열면 60% 확률로 단일 기사 껍데기가 나온다.

### 댓글·회원가입으로는 해결되지 않는다

2026-08-24에 도입한 댓글·회원가입은 이 위반의 답이 **아니다.**

- 정책이 요구하는 건 기능이 아니라 **페이지 위의 부가가치**다("논평을 추가하거나, 선별 게재
  또는 기타 부가가치"). 댓글 입력창은 논평이 아니라 논평을 받을 그릇이고, 현재 1만 페이지에
  댓글이 1개다. 빈 댓글창은 오히려 방치된 사이트 신호로 읽힌다.
- UGC는 통과를 돕기보다 **새 리스크를 만든다.** 사용자 생성 콘텐츠가 있으면 관리·신고 체계를
  요구받고, 정치 뉴스 댓글은 별도 정책(혐오·명예훼손)에 걸릴 수 있다.
- 닭과 달걀이다. 트래픽 없는 신규 사이트에 댓글이 쌓일 리 없고, 기다리는 동안 심사는 계속
  떨어진다.

| -------------------------- | ------------------ | --------- |

- [x] **sitemap에서 제외** ✅ (2026-08-27) — `findClusterRefs()`를 `findIndexableClusterRefs()`로
      교체. 성향 그룹 수는 Prisma로 표현할 수 없어 `$queryRawUnsafe`다.

### P0-2. 클러스터 페이지에 우리가 쓴 텍스트를 넣기

비어 있는 `Cluster.summary`가 정확히 이 자리다. **LLM 없이도** 이미 가진 데이터로 원본 분석
문장을 만들 수 있다.

- [x] **보도 편중 문장** ✅ (2026-08-27) — "11개 언론사가 이 사건을 보도했습니다 — 진보 2곳,
      중도 5곳, 보수 4곳."
- [x] **침묵한 진영 명시** ✅ (2026-08-27) — "보수 성향 매체 3곳(조선일보·동아일보·세계일보)에서는
      관련 보도가 확인되지 않았습니다."
      → **이 서비스의 가장 강력한 고유 정보다.** 원문 어디에도 없고, 우리 데이터로만 나온다.
      "다루지 않았다"가 아니라 **"확인되지 않았다"** 로 쓴다 — 우리가 아는 건 수집한 피드에
      없었다는 사실뿐이고, 지면에 실렸는데 RSS에 안 실렸을 수 있다.
- [x] **보도 시차** ✅ (2026-08-27) — "최초 보도는 뉴시스(05:00), 보수 성향 매체는 6시간 뒤에
      따라왔습니다." 진영별 **최초** 시각으로 계산해 같은 진영의 늦은 후속 기사에 끌려가지 않는다.
      1시간 미만이면 문장을 만들지 않는다.
- [ ] **제목 프레이밍 차이** — 성향별 제목에서만 등장하는 어휘 대조(진보 "특검" / 보수 "야당 공세").
      토큰화 + 성향별 빈도차로 계산 가능. 난이도가 가장 높으니 마지막에.

구현: `server/clustering/summary.ts`(순수 함수) → `clusterDay`의 `createMany`가 `summary`를
함께 채운다. 표시는 `ClusterDetailView`가 이미 `cluster.summary`를 렌더하므로 **UI 수정이
없었다.** `meta description`·OG·JSON-LD도 `metaDescription()`이 summary를 우선 쓰므로 함께 덮인다.

**언론사 이름 뒤에 조사를 붙이지 않는다.** "…였고"는 받침에 따라 "이었고"가 되어야 하고
("서울신문이었고"), SBS 같은 알파벳 이름까지 얹히면 규칙이 늘어난다. 이름 뒤를 쉼표로 끊었다.

> ⚠️ **LLM 요약을 붙일 거면 하루 상위 이슈 몇 개로만 제한한다.** 1만 개를 자동 생성하면 이번엔
> Google의 `scaled content abuse`(대량 생성 콘텐츠 남용)에 걸린다. 위반 하나를 다른 위반으로
> 바꾸는 셈이다. 규칙 기반 문장이 안전하고, 데이터에 근거해 매번 다르므로 템플릿 티도 덜 난다.

### P1-2. 사이트 레벨 고유 페이지 (E-E-A-T 신호)

현재 정적 페이지가 약관·개인정보처리방침뿐이다. **심사자가 "누가 왜 만들었나"를 확인할 곳이 없다.**

- [x] **`/about` — 소개 및 방법론** ✅ (2026-08-27) — 파이프라인 4단계(수집·임베딩·묶기·요약),
      성향 5단계 배치와 **분류의 성격**, 화면 읽는 법, **한계 6가지**, 데이터·문의.
      언론사 표는 `OUTLETS`에서 렌더해 명단이 코드와 어긋나지 않는다.
      푸터·sitemap(priority 0.7)에 링크.

  > **분류 근거를 지어내지 않았다.** launch-todo에 "어떤 연구를 참고했는지 출처가 없다"고
  > 적혀 있었고, 실제로 없다. 없는 출처를 붙이는 것이 그것대로 감점이므로
  > **"운영자가 정한 상대적 위치이며 특정 연구의 측정치가 아니다, 이견이 타당할 수 있다"**
  > 고 그대로 밝혔다. 심사에서는 정직한 한계 고지가 가짜 인용보다 낫다.

- [x] **`/outlets` · `/outlets/[id]` — 언론사별 페이지** ✅ (2026-08-27)
      보도량 추이(최근 30일), **단독 보도 비율**, **최초 보도 횟수**, 같은 이슈를 함께 다룬
      매체 Top 5, 참여한 최근 이슈(색인 대상만 링크).
      전부 우리가 계산한 값이라 **복제 텍스트가 0이다.** 허브 1개 + 상세 17개가 색인에 들어간다
      (기사 0건인 시사인은 `noindex, follow`).
      `meta description`도 집계 문장을 그대로 쓴다 — 예: "2026년 6월 29일부터 … 기사 1,407건을
      수집했고, 1,297개 이슈에 등장했습니다. 그중 775개(59.8%)는 다른 매체에서 확인되지 않은
      단독 보도이고, 807개 이슈에서는 가장 먼저 보도했습니다."
- [ ] **`/weekly` — 주간 리포트.** "이번 주 가장 성향이 갈린 이슈 10선". 정책이 명시한
      **선별 게재(curation)** 그 자체다. 자동 생성이어도 선별 기준이 분명하면 부가가치로 인정된다.

### P1-3. 목록에서도 선별 보여주기

## 이 서비스의 통과 가능성 — 정직한 평가

**가능하다. 단 현재 형태로는 아니다.**

뉴스 애그리게이터는 AdSense 심사에서 원래 난이도가 높은 카테고리다. 금지는 아니지만 부가가치
입증 책임이 전적으로 우리 쪽에 있다. 다행히 이 서비스에는 **입증할 부가가치가 실재한다** —
"같은 사건을 진보/보수가 어떻게 다르게 다뤘는가, 누가 침묵했는가"는 원문 어디에도 없는
정보이고, 그걸 계산하는 파이프라인이 이미 매일 돌고 있다.

문제는 그 결과가 **문장으로 존재하지 않는다**(P0-2)는 것과 **가치가 성립하는 11%에 나머지
89%를 섞어 색인했다**(P0-1)는 것이다. 둘 다 코드로 해결 가능한 문제다.

## 부록 — 진단 재현 쿼리

```sql
-- 클러스터 크기 분포
SELECT "articleCount" AS n, count(*) FROM "Cluster"
WHERE "articleCount" <= 6 GROUP BY 1 ORDER BY 1;

-- 성향 다양성 분포 (spread = 등장하는 leaning 종류 수)
SELECT spread, count(*) FROM (
  SELECT c.id, count(DISTINCT o.leaning) AS spread
  FROM "Cluster" c
  JOIN "Article" a ON a."clusterId" = c.id
  JOIN "Outlet" o ON o.id = a."outletId"
  GROUP BY c.id
) t GROUP BY 1 ORDER BY 1;

-- P0-1 색인 기준별 잔존 페이지 수
WITH c AS (
  SELECT cl.id, cl."articleCount" AS n,
         count(DISTINCT CASE WHEN o.leaning IN ('left','center_left') THEN 'prog'
                             WHEN o.leaning IN ('right','center_right') THEN 'cons'
                             ELSE 'neut' END) AS groups
  FROM "Cluster" cl
  JOIN "Article" a ON a."clusterId" = cl.id
  JOIN "Outlet" o ON o.id = a."outletId"
  GROUP BY cl.id, cl."articleCount"
)
SELECT count(*) AS total,
       count(*) FILTER (WHERE n >= 3 AND groups >= 2) AS keep
FROM c;

-- 자체 작성 텍스트 존재 여부 / 복제 텍스트 길이
SELECT count(*) FILTER (WHERE summary IS NOT NULL) AS with_summary FROM "Cluster";
SELECT avg(length(description))::int, max(length(description)) FROM "Article";

-- 오염 날짜
SELECT "bucketDate"::text, count(*) FROM "Cluster"
WHERE "bucketDate" < '2026-06-01' GROUP BY 1 ORDER BY 1;
```
