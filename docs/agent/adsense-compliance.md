> **복제된 콘텐츠가 있는 화면에 Google 게재 광고**

프로덕션 DB 실측(2026-08-25). 재현 쿼리는 문서 맨 아래 부록에 있다.

**핵심 진단 두 줄.**

1. 우리 서비스의 부가가치(성향 분포·보도량 비교)는 **막대그래프와 숫자로만 존재하고 문장으로
   존재하지 않는다.** `Cluster.summary` 필드는 스키마에만 있고 `server/clustering/daily.ts`의
   `createMany`가 채우지 않는다. 화면 위 텍스트의 100%가 남의 것이다.
2. 그 부가가치가 **성립하는 페이지는 11%인데 100%를 색인에 올렸다.** 심사자가 `/clusters/<id>`를
   랜덤으로 열면 60% 확률로 단일 기사 껍데기가 나온다.

### 댓글·회원가입으로는 해결되지 않는다

2026-08-24에 도입한 댓글·회원가입은 이 위반의 답이 **아니다.**

- 정책이 요구하는 건 기능이 아니라 **페이지 위의 부가가치**다("논평을 추가하거나, 선별 게재
  또는 기타 부가가치"). 댓글 입력창은 논평이 아니라 논평을 받을 그릇이고, 현재 1만 페이지에
  댓글이 1개다. 빈 댓글창은 오히려 방치된 사이트 신호로 읽힌다.
- UGC는 통과를 돕기보다 **새 리스크를 만든다.** 사용자 생성 콘텐츠가 있으면 관리·신고 체계를
  요구받고, 정치 뉴스 댓글은 별도 정책(혐오·명예훼손)에 걸릴 수 있다.
- 닭과 달걀이다. 트래픽 없는 신규 사이트에 댓글이 쌓일 리 없고, 기다리는 동안 심사는 계속
  떨어진다.

## P0 — 재심사 요청 전에 반드시 (이것만 해도 결과가 갈린다)

### P0-1. 껍데기 페이지를 색인에서 제거

가장 싸고 효과가 크다. 페이지 수가 5배 줄어도 **평균 품질이 5배 오르는 쪽이 심사에 유리하다.**

**색인 기준: `articleCount >= 3 AND 성향 그룹(진보/중도/보수) 2개 이상`**

실측 영향:

| 기준                       | 색인 대상 클러스터 | 하루 신규 |
| -------------------------- | ------------------ | --------- |
| 현재(전량)                 | 10,083             | 80~250    |
| `n>=3 && groups>=2` (채택) | **1,903** (18.9%)  | **약 40** |
| `n>=3` 만                  | 2,278              |           |
| `n>=5 && groups>=2`        | 992                |           |

- [ ] **sitemap에서 제외** — `src/app/sitemap.ts`가 쓰는 `findClusterRefs()`
      (`server/queries/clusters.ts:59`)에 필터 추가. 성향 그룹 수는 Prisma로 표현하기 번거로우니
      `$queryRaw`로 뽑는 편이 낫다.
- [ ] **`robots: noindex` 부여** — `src/app/clusters/[id]/page.tsx`의 `generateMetadata`에서
      기준 미달이면 `robots: { index: false, follow: true }`. `follow`는 남겨 링크 그래프를 유지한다.
- [ ] **날짜 페이지도 같은 기준으로** — 색인 가능한 클러스터가 0개인 날짜는 `noindex`.
      실측상 78일 중 **58일**이 남는다. `src/app/d/[date]/page.tsx`에 이미 "기사 없는 날짜
      noindex" 로직이 있으니 조건만 강화하면 된다.
- [ ] **오염 날짜 데이터 정리** — `bucketDate < 2026-06-01`인 클러스터 20개(기사 21건).
      RSS `pubDate`가 2023-03을 달고 온 잔재다(`scripts/collect.ts`의 `MAX_PAST_DAYS` 도입 이전
      수집분). `/d/2023-03-10` 같은 URL이 색인되면 그것만으로 품질 감점이다.

> ⚠️ **접근 자체를 막지 않는다.** 목록·상세는 그대로 열리고 색인만 뺀다. 사용자에겐 손실이
> 없고 크롤러에게만 "이건 대표 페이지가 아니다"라고 말하는 것이다.

### P0-2. 클러스터 페이지에 우리가 쓴 텍스트를 넣기

비어 있는 `Cluster.summary`가 정확히 이 자리다. **LLM 없이도** 이미 가진 데이터로 원본 분석
문장을 만들 수 있다.

- [ ] **보도 편중 문장** — "이 이슈는 진보 매체 7곳이 보도했고 보수 매체는 1곳뿐입니다."
- [ ] **침묵한 진영 명시** — "조선일보·중앙일보·동아일보는 이 사건을 다루지 않았습니다."
      → **이 서비스의 가장 강력한 고유 정보다.** 원문 어디에도 없고, 우리 데이터로만 나온다.
- [ ] **보도 시차** — "최초 보도는 한겨레(06:12), 보수 매체는 9시간 뒤에 따라왔습니다."
      `ClusterDetail.timeline`에 이미 있는 데이터다.
- [ ] **제목 프레이밍 차이** — 성향별 제목에서만 등장하는 어휘 대조(진보 "특검" / 보수 "야당 공세").
      토큰화 + 성향별 빈도차로 계산 가능. 난이도가 가장 높으니 마지막에.

구현 위치: `server/clustering/daily.ts`의 `clusterDay` 트랜잭션에서 `createMany` 시점에
`summary`를 함께 채운다. 표시는 `src/widgets/cluster-detail/ui/ClusterDetailView.tsx`가
이미 `cluster.summary`를 렌더하므로 **UI 수정 없이 바로 나온다.**

> ⚠️ **LLM 요약을 붙일 거면 하루 상위 이슈 몇 개로만 제한한다.** 1만 개를 자동 생성하면 이번엔
> Google의 `scaled content abuse`(대량 생성 콘텐츠 남용)에 걸린다. 위반 하나를 다른 위반으로
> 바꾸는 셈이다. 규칙 기반 문장이 안전하고, 데이터에 근거해 매번 다르므로 템플릿 티도 덜 난다.

## P1 — 통과 확률 강화 (P0와 함께 하면 가장 좋다)

### P1-1. 복제 텍스트 비중 낮추기

- [ ] 상세 페이지의 214자 발췌 × 최대 15개가 페이지 텍스트의 대부분이다. P0-2를 넣은 뒤
      **표시 길이를 80~100자로 더 줄이거나 아예 뺀다.** 저장은 300자를 유지해도 되고
      (임베딩 입력), 표시만 줄이면 된다. 제목은 비교 대상이므로 남긴다.
- [ ] 목표는 **원본/복제 텍스트 비율 역전.** P0-2 문장이 3~4줄 들어가고 발췌가 짧아지면
      페이지의 무게중심이 우리 쪽으로 넘어온다.

### P1-2. 사이트 레벨 고유 페이지 (E-E-A-T 신호)

현재 정적 페이지가 약관·개인정보처리방침뿐이다. **심사자가 "누가 왜 만들었나"를 확인할 곳이 없다.**

- [ ] **`/about` — 소개 및 방법론.** 성향 분류 기준과 근거, 클러스터링 방식(임베딩 + HAC,
      threshold 0.62), 데이터 출처와 수집 주기, **한계와 편향 고지.**
      → launch-todo.md의 미완료 항목 "언론사 성향 분류 근거 투명성"과 같은 작업이다.
      뉴스 성향 분류는 논쟁적이라 근거를 안 밝히면 그것대로 감점이다.
- [ ] **`/outlets/[id]` — 언론사별 페이지.** 보도량 추이, 주로 다루는 이슈, 다른 매체와의
      보도 중복률. 전부 우리가 계산한 값이고 **복제가 0인 페이지다.** 18개 언론사 = 18개
      고품질 색인 페이지.
- [ ] **`/weekly` — 주간 리포트.** "이번 주 가장 성향이 갈린 이슈 10선". 정책이 명시한
      **선별 게재(curation)** 그 자체다. 자동 생성이어도 선별 기준이 분명하면 부가가치로 인정된다.

### P1-3. 목록에서도 선별 보여주기

- [ ] 홈·날짜 페이지 목록에 1건짜리 클러스터가 그대로 섞여 나온다(정렬이 `articleCount desc`라

## 이 서비스의 통과 가능성 — 정직한 평가

**가능하다. 단 현재 형태로는 아니다.**

뉴스 애그리게이터는 AdSense 심사에서 원래 난이도가 높은 카테고리다. 금지는 아니지만 부가가치
입증 책임이 전적으로 우리 쪽에 있다. 다행히 이 서비스에는 **입증할 부가가치가 실재한다** —
"같은 사건을 진보/보수가 어떻게 다르게 다뤘는가, 누가 침묵했는가"는 원문 어디에도 없는
정보이고, 그걸 계산하는 파이프라인이 이미 매일 돌고 있다.

문제는 그 결과가 **문장으로 존재하지 않는다**(P0-2)는 것과 **가치가 성립하는 11%에 나머지
89%를 섞어 색인했다**(P0-1)는 것이다. 둘 다 코드로 해결 가능한 문제다.

## 부록 — 진단 재현 쿼리

```sql
-- 클러스터 크기 분포
SELECT "articleCount" AS n, count(*) FROM "Cluster"
WHERE "articleCount" <= 6 GROUP BY 1 ORDER BY 1;

-- 성향 다양성 분포 (spread = 등장하는 leaning 종류 수)
SELECT spread, count(*) FROM (
  SELECT c.id, count(DISTINCT o.leaning) AS spread
  FROM "Cluster" c
  JOIN "Article" a ON a."clusterId" = c.id
  JOIN "Outlet" o ON o.id = a."outletId"
  GROUP BY c.id
) t GROUP BY 1 ORDER BY 1;

-- P0-1 색인 기준별 잔존 페이지 수
WITH c AS (
  SELECT cl.id, cl."articleCount" AS n,
         count(DISTINCT CASE WHEN o.leaning IN ('left','center_left') THEN 'prog'
                             WHEN o.leaning IN ('right','center_right') THEN 'cons'
                             ELSE 'neut' END) AS groups
  FROM "Cluster" cl
  JOIN "Article" a ON a."clusterId" = cl.id
  JOIN "Outlet" o ON o.id = a."outletId"
  GROUP BY cl.id, cl."articleCount"
)
SELECT count(*) AS total,
       count(*) FILTER (WHERE n >= 3 AND groups >= 2) AS keep
FROM c;

-- 자체 작성 텍스트 존재 여부 / 복제 텍스트 길이
SELECT count(*) FILTER (WHERE summary IS NOT NULL) AS with_summary FROM "Cluster";
SELECT avg(length(description))::int, max(length(description)) FROM "Article";

-- 오염 날짜
SELECT "bucketDate"::text, count(*) FROM "Cluster"
WHERE "bucketDate" < '2026-06-01' GROUP BY 1 ORDER BY 1;
```
